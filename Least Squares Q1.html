1 · What nsolve looks for

A line has two numbers: a slope w and an intercept b. Each data point pays the square of how far the line misses it (the orange squares). Least squares picks the line with the smallest total W1 §3.1. Drag the line's ends, the orange dot on the right, or the points themselves.

The right plot is the total squared error for every (w, b). It is a bowl, and each ring is a line of equal error. The green star is the bottom, and it is the answer nsolve returns. The slope of the bowl at your dot is the pair of numbers ∂J/∂w, ∂J/∂b: both are zero at the star.

Try it. Switch the ones column off. The line must pass through the origin, so the dot can only slide along the dashed line b = 0, and the star moves to the best spot on that line. The hollow star is the better answer you gave up. Then switch the axes to centred: the rings turn rounder, which is why the notes centre the data first W1 §3.1 W2 §2.3.

3 · The same equation as geometry

Take two data points, one feature and no ones column. Each column of X is then an arrow in the plane: one axis per data point. Fitting means finding the point w·x on the line through x that is closest to y. Drag any of the three dots, or use the slider.

Closest means a right angle. The miss e = ŷ − y is shortest when it meets the line at 90°, which means x·e = 0. Written out, xᵀ(xw − y) = 0, which is XᵀXw = Xᵀy with one column. Solving gives w = Σxy / Σx² W2 §1.2.

With more columns, e is at a right angle to every column of X at once. That is Xᵀe = 0, the matrix equation. In section 1 the two numbers Σe and Σx·e are exactly these dot products, with the ones column and with x.

5 · poly_fit: more columns, same solver

poly_fit does not change nsolve. It changes X: the columns become 1, x, x², x³, …. The curve bends, but the model is still linear in w, so the error is still a bowl and XᵀXw = Xᵀy still finds its bottom W1 §3.4. The catch is that more columns can fit the noise. Pick a degree.

np.linalg.inv raises LinAlgError: Singular matrix. Your except branch runs and pinv returns the minimum-norm answer.

Columns differing by about 1e-9

8 · Three things to check in your cells

Found while reproducing your notebook's numbers. Your Q1b and Q1c results reproduce exactly (section 6), so the maths is right. These are about the code around it.

nsolve crashes as written

The line np.column_stack([np.ones(X.shape[0], 1), X]) raises TypeError: Cannot interpret '1' as a data type, because the second argument of np.ones is a dtype. The array printed under your test cell must come from an earlier version. Aug_X is never used afterwards, so delete the line. The ones column belongs in line_fit, where you already have it.

Inverse versus solve

The notes say to use a stable solver and not to form the inverse explicitly W1 §3.1 W2 §1.5. np.linalg.solve(XᵀX, Xᵀy) does that. Your pinv fallback matches the notes' X†y. Section 7 shows that the except branch only fires on an exactly singular matrix.

Two meanings of "L2 error"

line_fit returns Σe² and poly_fit returns Σe²/N. The notes report MSE W1 §4.4. Return the same quantity from both, and say which one in the docstring. Your test cells already divide by N, so the printed numbers are MSE.
